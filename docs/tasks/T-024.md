# T-024 · 원청별 이메일 기본 문구 설정

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 1. 마스터 데이터 |
| 분류 | 이메일·알림 |
| 우선순위 | P2 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-022](T-022.md) 원청 등록·수정 폼 |
| 요구사항 근거 | §19 이메일 발송, §25 이메일 문구 설정 |
| 주요 위치 | `app/owner/clients/[id]/email-template/` |

## 목적

발송할 때마다 문구를 새로 쓰지 않도록 기본값을 저장하고, 업체명·연월·파일명이 자동으로 채워지게 한다.

## 요구사항 근거 (설계.md 인용)

> 자동으로 삽입할 수 있는 항목: 원청 업체명, 정산 연도, 정산 월, 파일명, 수정본 여부

## 작업 범위

- 제목·본문 템플릿 입력
- 치환 토큰 5종 정의와 삽입 버튼
- 치환 결과 실시간 미리보기
- 기본 템플릿 시드 제공

## 완료 기준

- [x] 토큰이 포함된 문구가 미리보기에서 실제 값으로 치환된다 — 브라우저로 5종 토큰 전부 치환 확인
- [x] 원청별로 다른 문구가 저장된다 — 브라우저로 제목 수정 후 저장, DB에 그 값이 실제로 들어간 것 확인
- [x] 본문이 비어 있으면 기본 템플릿이 적용된다 — **adversarial-reviewer 지적으로 수정**: 기본값 적용(`||`)이 화면 컴포넌트 안에만 있어서, DB를 직접 읽는 다른 코드(T-074 등)가 그대로 쓰면 빈 본문이 나갈 위험이 있었다. `lib/email/template.ts`에 `resolveSubjectTemplate`/`resolveBodyTemplate`로 옮겨서 T-074도 그대로 재사용하면 되게 고침. `substituteTemplate`도 치환값을 문자열로 바로 넘기면 `$&` 같은 특수 치환 패턴으로 해석될 수 있던 것을 함수로 넘기게 고침(리터럴 치환 보장)

## 연관 작업

- [T-074](T-074.md) — 이메일 문구 치환과 발송 전 편집

## 쉬운 설명

원청 상세 페이지에 "이메일 문구 설정" 하위 화면을 만든다. `clients`
테이블에는 이미 `email_subject_template`·`email_body_template`(기본값 빈
문자열) 컬럼이 있다. 제목·본문에 `{{업체명}}` 같은 토큰을 넣으면 실시간
미리보기에서 샘플 값으로 치환돼 보인다. 치환 로직은 T-074(실제 발송)도
재사용할 것이므로 `lib/`에 순수 함수로 둔다.
