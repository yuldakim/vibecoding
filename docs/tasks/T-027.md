# T-027 · 품목 추가·수정

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 1. 마스터 데이터 |
| 분류 | 기능 구현 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-026](T-026.md) 원청별 품목 목록 화면 |
| 요구사항 근거 | §4 품목 관리 |
| 주요 위치 | `app/owner/items/` |

## 목적

'차렵이불' 같은 분류가 아니라 '메이퀸 꽃 차렵이불'처럼 원청이 실제로 쓰는 이름을 그대로 등록하게 한다.

## 요구사항 근거 (설계.md 인용)

> 품목은 `차렵이불` 같은 일반 분류가 아니라 원청에서 사용하는 구체적인 이름으로 관리한다.

## 작업 범위

- 품목 추가 폼(원청 고정, 품목명)
- 같은 원청 내 중복 이름 차단과 안내
- 품목명 앞뒤 공백 정리
- 단순 오타 수정과 이름 변경(T-032)의 구분 안내

## 완료 기준

- [x] 중복 이름 등록 시 기존 품목을 알려준다 — `addItem`이 같은 원청·같은 이름(합쳐지지 않은 것만)이 있으면 insert 없이 `error=duplicate`(또는 기존 품목이 숨김 상태면 `error=duplicate_hidden`)로 redirect. 실제 DB로 재현: 같은 이름 재시도 시 기존 행이 조회되어 두 번째 insert가 안 일어남을 확인. adversarial-reviewer 지적으로 "숨긴 품목과 이름이 겹쳐서 기본 목록에 안 보이는데 '이미 있다'는 메시지만 뜨고 어디 있는지 안내가 없던" 문제를 고쳐 숨김 여부를 구분해 안내함
- [x] 등록 즉시 목록에 반영된다 — `revalidatePath`로 확인(송장 작성 화면(T-035)이 아직 없어 "선택된다"는 문자 그대로는 못 봄 — 그 화면이 생기면 이 items 테이블을 그대로 읽으면 됨)
- [x] 품목이 항상 한 원청에 귀속된다 — `clientId`가 hidden input으로 고정, 폼에서 원청 선택 불가

## 주의사항

- 이름 변경은 이력이 남는 별도 기능(T-032)이다. 여기서는 신규 등록과 단순 수정만 다룬다.
