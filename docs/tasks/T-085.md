> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 요구사항 근거 | §22 직원 화면 |

## 목적

직원은 사장님에게 전달하는 역할만 한다. 정보는 최소한으로, 대신 놓치지 않게 보여준다.

## 요구사항 근거 (설계.md 인용)

> 다음 알림만 표시한다. 사장님 정산 확인 필요, 자동 발송 예정일, 정산서 발송 실패
>
> 직원 알림은 원청별 발송 예정일 7일 전부터 표시한다.
>
> `사장님께 전달했어요` 같은 확인 버튼은 만들지 않는다.

## 작업 범위

- 알림 3종만 표시
- 발송 예정일 7일 전부터 노출하는 시점 계산
- 금액·단가 필드가 응답에 없음을 확인
- 확인 버튼을 만들지 않음

## 완료 기준

- [x] 직원 화면에 4번째 알림 종류가 나타나지 않는다 — `getNotificationsForRole("staff")`가 `target_role in ('staff','both')`로 DB 단계에서 이미 owner 전용 알림을 뺀다. 실제 DB에 staff 3종 + owner 1종을 섞어 넣고 쿼리를 재현해 owner 알림이 결과에 아예 없는 것(`owner-only kind leaked? false`) 확인. 화면 쪽에도 `kind in LABELS`(3종 화이트리스트) 필터를 추가로 둬서 target_role이 잘못 입력된 행도 안 새게 이중 방어
- [x] 8일 전에는 안 보이고 7일 전부터 보인다 — 판정 로직 자체는 T-083의 `shouldNotifyStaffAutoSendUpcoming`(범위 밖, 재사용만). 이 화면은 `notifications` 테이블에 이미 있는 행을 읽기만 하므로, 실제 행을 만들고 지우는 배치(T-078 등)가 붙기 전까지는 "테이블에 있으면 보여주고 없으면 안 보여준다"까지만 검증 가능 — 그 부분은 실제 확인함
- [x] 응답 페이로드에 금액이 없다 — `getNotificationsForRole`의 select 컬럼(`id, kind, target_role, ref_type, ref_id, created_at, resolved_at`)을 실제 쿼리 결과로 확인, 금액·단가 필드 없음
