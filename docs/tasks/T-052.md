> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 분류 | 기능 구현 |

## 목적

사장님이 가장 자주 하는 입력 작업이다. 입력 즉시 저장되고 실수는 되돌릴 수 있어야 한다.

## 작업 범위

- 표 안 인라인 입력과 즉시 저장
- 정수(원) 검증과 천 단위 구분 표시
- 변경 시 이전 값·새 값·시각 기록
- 저장 성공·실패 피드백

## 완료 기준

- [x] 입력한 단가가 새로고침 후에도 유지된다 — `upsertMonthlyPrice`가 DB에 실제로 update/insert. 테스트 원청·품목으로 12000원 저장 후 재조회해서 유지 확인(브라우저 "저장됨" 표시까지 확인)
- [x] 소수점·음수가 저장되지 않는다 — **adversarial-reviewer가 치명으로 지적**: 이전 버전은 `formatDisplay`가 비숫자 문자를 조용히 지워서 "3,000.00" 붙여넣기가 300000(100배)으로, "-100"이 100으로 저장되는 사고가 있었다(거부가 아니라 다른 값으로 둔갑). `parseDigits`로 고쳐 콤마 외의 비숫자 문자가 하나라도 있으면 입력 자체를 통째로 거부하고 에러 문구를 띄우도록 수정. "3.5"·"-100"·"abc" 모두 값이 바뀌지 않고 거부되는 것으로 재확인
- [x] 변경 이력이 조회된다 — `price_change_history`에 old_price/new_price/changed_by_role이 실제로 쌓이는 것을 확인. **adversarial-reviewer가 치명으로 지적**: 이전 버전은 셀이 blur될 때마다 값이 안 바뀌었어도 무조건 update+이력 insert를 해서, 빈 셀을 클릭만 했다 나와도 `unit_price=null` 유령 행과 `old=null/new=null` 거짓 이력이 쌓였고, 이 유령 행 때문에 T-053 복사가 "이미 값 있음"으로 오판해 전부 건너뛰는 연쇄 버그로 이어졌다. `upsertMonthlyPrice`에 `oldPrice === parsed`면 아무것도 쓰지 않는 가드를 추가해 근본 수정

검증: `npx tsc --noEmit` 전체 통과. `requireRole("owner")`가 `upsertMonthlyPrice` 맨 앞에 있음. 인풋 높이도 56px(h-14)로 맞춤(원래 48px이던 것을 코드-작성.md 버튼/입력 높이 기준에 맞게 수정).
