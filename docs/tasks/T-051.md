## 목적

정산 금액의 출발점이다. 어떤 조합에 단가가 있고 없는지 한눈에 보이게 한다.

## 요구사항 근거 (설계.md 인용)

> 봉제 단가는 다음 조건으로 관리한다: 원청, 품목, 사이즈, 적용 연도와 월

## 작업 범위

- 원청·연월 선택
- 품목×사이즈 단가표 렌더링
- 미정 항목 강조 표시
- 품목명 검색·필터
- 단가가 공급가액 기준(부가세 별도)임을 화면에 명시

## 완료 기준

- [x] 선택한 월의 단가가 표로 보인다 — 브라우저로 실제 확인: 품목×사이즈 매트릭스에 저장된 단가(3,000원)가 정확한 칸에 표시됨
- [x] 미정 항목이 눈에 띄게 구분된다 — 브라우저로 확인: `unit_price`가 명시적으로 null인 경우와 그 달 단가 행 자체가 없는 경우 둘 다 빨간 "미정" 배지로 동일하게 표시(코드·실측 둘 다 확인)
- [x] 품목 100개 규모에서 화면이 쓸 만하다 — 품목 100개로 테스트 데이터를 만들어 쿼리 로직 재현, 정상 응답 확인

검증: `getSessionForRole("owner")`가 페이지 최상단, DB 조회 전에 걸려 있음을 코드로 확인(T-016 헬퍼의 첫 실사용). 세션 없이 `/owner/prices` 요청 시 proxy가 307로 `/owner`에 리다이렉트하는 것도 확인.

## 주의사항

- **(리뷰에서 발견해 수정함)** 기본 연월을 `new Date()`의 `getFullYear()`/`getMonth()`로 계산했는데, 서버가 UTC로 돌면 매월 1일 KST 오전 0~9시 사이에 지난달로 잡히는 버그가 있었다(`lib/notifications/rules.ts`가 이미 겪은 것과 같은 함정). `lib/date/kst.ts`의 `toKstYearMonth()`로 고쳤다 — 날짜·월이 필요한 화면은 항상 이 파일을 거친다.
- **(리뷰에서 발견해 수정함)** `month` 쿼리 파라미터가 `YYYY-MM` 형식이 아니면(Firefox는 `<input type="month">`를 지원하지 않아 텍스트 입력으로 떨어질 수 있음, URL 손타이핑도 있음) Postgres 캐스팅이 실패해 **조회 실패가 "전 칸 미정"으로 위장**됐다 — "미정"은 이 도메인에서 실제 의미 있는 상태(§10, 단가 확인 요청 대상)라 조회 오류와 구분해야 한다. 지금은 형식이 안 맞으면 기본값(오늘 KST 기준 이번 달)으로 되돌리고, DB 조회 자체가 실패하면 별도 에러 문구를 보여준다.
- 검색어에 `%`/`_`를 그대로 넣으면 LIKE 와일드카드로 해석되던 문제를 `lib/db/like.ts`의 `escapeLike()`로 고쳤다(원청 목록 화면(T-021)이 먼저 만든 걸 공유 위치로 옮김 — 품목 목록(T-026)도 같은 걸 쓴다).
- `components/ui/table.tsx`는 `overflow-x-auto`만 제공한다 — 품목×사이즈 단가 매트릭스는 사이즈가 많아지면 휴대폰 폭에서 표 자체가 가로 스크롤된다(페이지는 안 깨짐). 이건 T-017의 기존 설계 결정이라 이번 작업에서 고치지 않았다 — 실사용에서 불편하면 T-017 쪽에서 카드형 대안을 검토한다.
