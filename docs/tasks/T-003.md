## 목적

데이터베이스와 인증의 기반을 붙인다. 마이그레이션을 파일로 관리해야 이후 스키마 변경이 추적되므로 CLI 기반 마이그레이션 체계를 함께 세운다.

## 작업 범위

- Supabase 프로젝트 생성(또는 기존 프로젝트 지정)
- supabase CLI 설치와 `supabase link`
- 환경변수 3종(.env.local / Vercel) 설정
- 서버용·브라우저용 Supabase 클라이언트 헬퍼 작성
- `supabase migration new`로 첫 빈 마이그레이션 생성 확인

## 완료 기준

- [x] 로컬에서 Supabase에 쿼리 1건이 성공한다
- [x] service_role 키가 서버 코드에서만 쓰이고 클라이언트 번들에 포함되지 않는다
- [x] 마이그레이션 파일이 git에 커밋된다

## 주의사항

- 키는 전부 환경변수로만 참조하고 저장소에 커밋하지 않는다.
- 무료 요금제의 프로젝트 자동 일시정지 정책을 확인해 둔다.
- `supabase link`는 브라우저 OAuth 없이 `--token`(PAT)·`--password`(DB 비밀번호)로도 할 수 있지만, 둘 다 사용자만 줄 수 있는 값이라 이번 세션에서는 생략했다. MCP(`mcp__supabase__*`)가 이미 같은 프로젝트에 인증돼 있어 마이그레이션 적용은 당장 MCP로 대체한다. → [T-097](T-097.md) (`needs_decision`)

## 쉬운 설명

공장에서 데이터를 저장할 데이터베이스가 필요하다. 송장, 품목, 원청, 봉제 단가처럼 납품과 정산에 필요한 모든 정보가 들어가야 한다. 이 작업은 Supabase(클라우드 데이터베이스)를 프로젝트에 연결하고, 로컬 개발 환경에서 안전하게 쓸 수 있게 하는 일이다. 환경변수를 설정해서 데이터베이스 주소와 접근 키를 안전하게 관리하고, 서버와 브라우저에서 각각 다른 권한으로 데이터베이스에 접근하는 헬퍼 코드를 만든다. 마이그레이션 파일도 git에 저장해서 나중에 같은 환경을 다시 만들거나 다른 사람이 이어받을 때 설정이 유지되게 한다.

## 관련 파일

### 이미 있는 파일

| 파일 | 왜 관련 있나 |
| --- | --- |
| `package.json` | Supabase 클라이언트 라이브러리 설치 대상 |
| `app/`, `next.config.ts`, `tsconfig.json` | Next.js 프로젝트 구조의 일부 |

### 이 작업에서 만들 파일

| 파일 | 무엇 |
| --- | --- |
| `lib/supabase/server.ts` | 서버에서만 쓰는 Supabase 클라이언트 (service_role 키 사용) |
| `lib/supabase/client.ts` | 브라우저에서 쓰는 Supabase 클라이언트 (공개 키 사용) |
| `supabase/config.toml` | Supabase CLI 설정 파일 |
| `supabase/migrations/00000000000000_initial.sql` | 첫 마이그레이션 파일 (초기) |
| `.env.local` | 로컬 개발용 환경변수 (git에 커밋하지 않음) |
| `.env.example` | 환경변수 템플릿 (어떤 변수가 필요한지 보여주기) |
