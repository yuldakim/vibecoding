## 목적

메뉴를 역할별로 줄여 '복잡한 메뉴 최소화' 요구를 만족시키고, 주소를 직접 입력해도 사장님 화면에 못 들어가게 한다.

## 작업 범위

- 직원 메뉴(송장 중심 4~5개)와 사장님 메뉴 구성
- 미들웨어(Next.js 16 기준 파일명은 `proxy.ts` — 빌드가 `middleware.ts`를 deprecated로 경고해서 `npx @next/codemod middleware-to-proxy`로 마이그레이션함)에서 /owner-home 경로 역할 검사
- 권한 없는 접근 시 사장님 모드 입력 화면으로 유도
- 현재 역할 표시와 역할 전환 버튼

## 완료 기준

- [x] 직원 세션으로 /owner-home 경로에 접근하면 차단된다 — `curl`로 세션 없이 `/owner-home` 요청 시 307로 `/owner`에 리다이렉트되는 것 확인, 브라우저로 직원 계정 로그인 후에도 같은 경로 매칭 로직(`satisfiesRole`)이라 동일하게 차단됨을 코드로 확인
- [x] 직원 메뉴에 정산·단가 항목이 보이지 않는다 — 브라우저로 직원 로그인 시 `/home`에 4개 메뉴(새 송장 만들기/임시 송장 목록/확정 송장 목록/알림)만 뜨고, 사장님 로그인 시 `/owner-home`에 그 4개 + 정산 목록/월별 단가/원청 관리/품목 관리/공장 설정까지 9개가 뜨는 것을 실제 렌더로 확인
- [x] 역할 전환이 2번 이내 조작으로 된다 — `/home`의 "사장님 모드로" 버튼 1번 클릭 → `/owner`(비밀번호 입력) → 비밀번호 입력 후 1번 제출 → `/owner-home`. 반대 방향("직원 화면 보기")은 클릭 1번으로 바로 `/home`(이미 세션이 있어 비밀번호 재입력 없음)

## 주의사항

- `/owner`(비밀번호 입력 화면)는 이미 owner 세션이 있어도 다시 비밀번호를 요구한다 — 매끄럽지 않지만 버그는 아니다(T-014 범위 밖, 필요해지면 별도 작업으로).
- **(T-020/021/026/051/084/085 착수 직전에 발견해 수정함)** `Nav`의 `OWNER_ITEMS`가 원래 `/settlements`·`/prices`·`/clients`·`/items`·`/settings`(최상위)를 가리켰는데, 정작 그 화면들의 백로그 문서는 위치를 `app/owner/settlements/`처럼 `/owner/` 아래로 못박아 뒀다. 이 화면들을 만들기 전에 `Nav`를 문서에 맞춰 고쳐서(`/owner/settlements` 등), 화면 작업들이 프록시 가드가 실제로 걸리는 경로에 맞춰 만들어지게 했다. 사장님 "알림"도 직원용 `/notifications`(3종)와 구분되는 `/owner/notifications`(7종, T-084)로 분리했다.
- **(리뷰에서 발견해 수정함)** proxy 매처가 원래 `/owner-home/:path*`뿐이었는데, T-020·T-021·T-026·T-051·T-061 문서는 사장님 화면 주소를 `app/owner/...`(예: `/owner/clients`, `/owner/prices`)로 적어뒀다 — 매처가 그 경로들을 하나도 안 잡아서, 해당 화면이 만들어져도 라우트 가드가 안 걸릴 뻔했다. 지금은 매처가 `["/owner-home/:path*", "/owner/:path+"]`다. `/owner/:path+`(1개 이상)를 써서 로그인 화면 `/owner` 자체는 계속 빠진다(정규식으로 직접 검증: `/owner`→false, `/owner/clients`→true). 앞으로 사장님 전용 화면을 새로 만들 때는 반드시 `/owner-home/...` 또는 `/owner/...` 아래에 둬야 이 가드를 받는다 — 다른 경로에 만들면 각 페이지가 `getSessionForRole`을 직접 불러야 한다.
