## 목적

송장번호는 원청·연도와 무관한 하나의 일련번호이고 취소해도 재사용하지 않는다. 동시에 두 명이 확정해도 번호가 겹치면 안 된다.

## 요구사항 근거 (설계.md 인용)

> `확정하고 인쇄` 버튼을 누르는 순간 송장번호를 부여한다.
>
> 취소된 번호는 다시 사용하지 않는다.

## 작업 범위

- DB 시퀀스 기반 번호 발급(트랜잭션)
- draft → confirmed 상태 전이와 작성 시각 기록
- 동시 확정 테스트
- 6자리 0패딩 표시(000001)

## 완료 기준

- [ ] 두 기기에서 동시에 확정해도 번호가 중복되지 않는다
- [ ] 취소 후 다음 번호가 되돌아가지 않는다
- [ ] 확정 후 내용 수정 API가 거부된다

## 주의사항

- 번호를 앱 레벨에서 max+1로 계산하면 경쟁 상태가 생긴다. 반드시 DB 시퀀스를 쓴다.
