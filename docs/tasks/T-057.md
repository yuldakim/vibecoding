# T-057 · 송장 줄 예외 단가

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 3. 봉제 단가 |
| 분류 | 기능 구현 |
| 우선순위 | P1 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-056](T-056.md) 송장 줄 ↔ 단가 자동 매칭, [T-062](T-062.md) 정산 상세 표 화면 |
| 요구사항 근거 | §11 특정 송장 줄의 예외 단가 |
| 주요 위치 | `app/owner/settlements/[id]/` |

## 목적

월 기본 단가와 다른 단가가 특정 납품 건에만 적용되는 실제 업무를 반영한다. 다른 송장에는 영향이 없어야 한다.

## 요구사항 근거 (설계.md 인용)

> 월 기본 단가: 3,000원 / 특정 송장 줄의 예외 단가: 3,500원 / 해당 줄만 `수량 × 3,500원`으로 계산
>
> 예외 단가 적용 이유는 해당 품목 줄의 비고란에 적는다.

## 작업 범위

- 정산 내역 표에서 줄 단가 인라인 수정
- 예외 단가 저장(월 기본 단가와 분리) — **저장 위치는 `settlement_lines.override_unit_price`(이미 스키마에 있음).** `invoice_lines`에 새 컬럼을 만들지 않는다. `lib/prices/resolve.ts`(T-056)의 `resolveLinePrice`가 `lineExceptionPrice` 파라미터로 이 값을 그대로 받는 구조로 이미 맞춰져 있다 — 다른 곳에 또 저장하면 예외 단가가 두 곳에 생겨 어느 쪽이 정산에 반영되는지 갈린다(adversarial-reviewer가 T-056 리뷰에서 지적)
- 예외 적용 줄 시각적 표시
- 수정 전·후 단가와 시각 기록
- 비고에 사유 입력 유도

## 완료 기준

- [ ] 한 줄 단가를 바꿔도 같은 품목의 다른 줄은 그대로다
- [ ] 월별 단가표가 변경되지 않는다
- [ ] 수정 전후 값이 기록에 남는다
