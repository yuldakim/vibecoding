## 목적

'삭제 대신 상태'는 설계 전반의 원칙이다. 어딘가에 DELETE가 하나라도 남아 있으면 복구 불가능한 사고가 된다.

## 요구사항 근거 (설계.md 인용)

> 다음 정보는 완전히 삭제하지 않는다: 원청, 품목, 직원 계정, 확정 송장, 발송된 정산서, 월별 단가
>
> 과거 기록은 항상 조회할 수 있어야 한다.

## 작업 범위

- 6개 대상에 대한 DELETE 쿼리·API 전수 검색
- 임시 송장만 삭제 가능함을 확인
- 숨김·사용 중지·취소 후에도 과거 조회가 되는지 시나리오 확인
- 점검 결과 문서화

## 완료 기준

- [ ] 보존 대상 6종에 물리 삭제 경로가 없다
- [ ] 임시 송장은 삭제 가능하다
- [ ] 중지·숨김·취소된 대상의 과거 기록이 모두 조회된다
