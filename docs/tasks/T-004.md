# T-004 · 전체 DB 스키마 설계 확정

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 데이터 모델 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-003](T-003.md) Supabase 프로젝트 연결 |
| 요구사항 근거 | §3~§24 전반 |
| 주요 위치 | `docs/db-schema.md` |

## 목적

송장·단가·정산이 서로 얽혀 있어 테이블을 하나씩 즉흥적으로 만들면 반드시 뒤집힌다. 품목명 변경 이력 보존, 이월 처리, 예외 단가 같은 까다로운 요구를 미리 스키마에 반영한다.

## 요구사항 근거 (설계.md 인용)

> 품목 이름을 변경하거나 합쳐도 기존 송장에는 당시 사용한 이름을 그대로 보존한다.
>
> 다음 정보는 완전히 삭제하지 않는다.

## 작업 범위

- 엔티티 목록과 관계도(ERD) 작성
- 송장 줄에 '작성 당시 품목명 문자열'을 스냅샷으로 남기는 설계 확정
- 상태 컬럼 값 정의(송장·정산서·단가·발송)
- 삭제 대신 쓰는 상태 컬럼(사용중지/숨김/취소) 정의
- 인덱스 후보 정리(원청별 품목 검색, 월별 송장 조회)

## 주의사항

- 금액은 부동소수점 대신 정수(원 단위)로 저장한다.
- 송장 줄은 품목 id와 당시 품목명 문자열을 둘 다 갖는다.
