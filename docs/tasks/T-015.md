# T-015 · 사장님 비밀번호 변경·초기화 절차

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 인증·권한 |
| 우선순위 | P2 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-014](T-014.md) 사장님 모드 비밀번호 인증 |
| 요구사항 근거 | §2 사장님 |
| 주요 위치 | `scripts/reset-owner-password.ts` |

## 목적

설계상 비밀번호 찾기 기능은 없고 개발자가 초기화한다. 그 절차를 사람 손에 맡기지 않고 스크립트로 고정한다.

## 요구사항 근거 (설계.md 인용)

> 사장님이 비밀번호를 잊은 경우 개발자에게 요청하여 초기화한다.

## 작업 범위

- 사장님 설정 화면의 비밀번호 변경 폼(현재 비밀번호 확인)
- 초기화 CLI 스크립트(환경변수로 새 비밀번호 주입)
- 초기화 시 audit_logs 기록
- 운영 문서에 절차 기록

## 완료 기준

- [x] 사장님이 화면에서 비밀번호를 바꿀 수 있다 — `app/(owner-area)/owner-home/password/`. 브라우저로 실제 클릭·입력해 전체 흐름 확인: 현재 비밀번호 확인 → 새 비밀번호 저장 → `/owner-home`에 "비밀번호를 바꿨습니다" 성공 문구 표시 → 로그아웃 → 새 비밀번호로 재로그인 성공. `/owner-home`에 "비밀번호 변경" 링크도 추가해서 화면에서 이 경로에 실제로 도달할 수 있게 함(리뷰 전에는 URL을 직접 쳐야만 갈 수 있었음)
- [x] 스크립트로 초기화하면 즉시 새 비밀번호로 로그인된다 — `npm run reset-owner-password`를 실제로 실행, DB의 `owner_password_hash`가 바뀌고 `verifyPassword`로 즉시 통과하는 것 확인. 실패 카운트·잠금도 함께 풀리는 것 확인
- [x] 새 비밀번호가 명령 이력이나 저장소에 남지 않는다 — **(리뷰에서 발견해 수정함)** 처음엔 `NEW_OWNER_PASSWORD=값 npm run ...` 형태를 문서가 "안전하다"고 안내했는데, 이 형태는 bash/zsh와 PowerShell(PSReadLine) 양쪽 다 명령 히스토리에 평문으로 남는다 — 환경변수라는 것과 무관하게 명령줄에 값이 등장하면 남는다. 지금은 스크립트가 `node:readline`으로 대화형 프롬프트를 기본 경로로 받아 명령줄에 비밀번호가 아예 안 나타나게 고쳤다(환경변수는 CI 전용 예외로 문서에 남김). `audit_logs`의 before/after에는 `{changed: true/false}` 마커만 남기고 비밀번호 원문·해시는 안 넣음(실제 insert된 행으로 확인)

## 주의사항

- 비밀번호를 바꾸거나 초기화해도 **기존에 발급된 세션 쿠키는 무효화되지 않는다.** 세션은 무상태 HMAC 쿠키(최대 12시간 TTL)라 탈취된 쿠키가 있었다면 비밀번호를 바꿔도 그 쿠키는 계속 유효하다. 지금은 요구사항에 없어 구현하지 않았다 — 필요해지면 `factory_settings`에 `session_epoch` 같은 값을 두고 세션 페이로드와 비교하는 방식을 검토한다.
- 새 비밀번호 최소 길이(4자)가 `actions.ts`와 `scripts/reset-owner-password.ts` 두 곳에 각각 하드코딩돼 있다. 나중에 기준을 바꾸려면 두 곳 다 고쳐야 한다.
