> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 분류 | 기능 구현 |
| 우선순위 | P0 |

| 선행 작업 | [T-059](T-059.md) 월말 정산 내역 자동 생성, [T-067](T-067.md) 정산 최종 승인 |
| 요구사항 근거 | §17 뒤늦게 등록된 송장 이월 |
| 주요 위치 | `lib/settlements/carryover.ts` |

## 목적

발송이 끝난 정산서를 다시 건드리지 않으면서도 누락 없이 정산하기 위한 규칙이다. 판정 기준을 한 곳에 모은다.

## 요구사항 근거 (설계.md 인용)

> 특정 월의 정산서가 이미 승인된 뒤 해당 월 날짜로 새로운 송장이 확정되면 기존 정산서를 변경하지 않는다.
>
> 해당 송장은 다음 달 정산서로 이월한다.

## 작업 범위

- 송장 확정 시점과 해당 월 정산서 승인 상태 비교
- 이월 대상 표시 저장
- 이월 대상이 다음 달 정산 생성에 포함되도록 연결
- 이월 판정 기준 시각(승인 시각) 정의

## 완료 기준

- [ ] 승인 후 확정된 7월 송장이 8월 정산에 들어간다
- [ ] 기존 7월 정산서가 변경되지 않는다
- [ ] 승인 전 확정된 송장은 이월되지 않고 그 달에 들어간다

## 주의사항

- 판정 기준을 '승인 시각'으로 할지 '발송 시각'으로 할지에 따라 결과가 달라진다. 설계는 승인 기준이므로 승인 시각을 쓴다.
