# T-013 · 직원 로그인(계정 선택 방식)

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 인증·권한 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-005](T-005.md) 마이그레이션: 공장 정보·직원 계정 |
| 요구사항 근거 | §2 직원, §25 사용자 선택 화면 |
| 주요 위치 | `app/(auth)/` |

## 목적

50대 후반 사용자와 공장 직원이 비밀번호 없이 바로 쓰게 한다. 다만 직원 권한이 사장님 정보에 접근하지 못하도록 세션에 역할을 명확히 담는다.

## 요구사항 근거 (설계.md 인용)

> 직원은 로그인 화면에서 사용할 직원 계정을 선택하면 별도의 비밀번호 없이 바로 이용한다.

## 작업 범위

- 활성 직원 계정 목록을 큰 버튼으로 표시
- 선택 시 역할 'staff' 세션 쿠키 발급
- 세션 만료·재선택 처리
- 로그아웃(계정 바꾸기) 동작

## 완료 기준

- [x] 계정을 고르면 직원 첫 화면으로 이동한다 — 브라우저로 실제 클릭해 확인: `/staff`에서 테스트 계정 선택 → `/home` 이동 → "계정 바꾸기" → `/staff` 복귀 → 세션 없이 `/home` 직접 접근 시 가드가 `/staff`로 돌려보냄(테스트 계정은 삭제함). `npm run dev`는 병렬 작업이 끝난 뒤 돌렸다 — 개발 서버 기준 확인이고, 프로덕션 빌드(`force-dynamic` 추가 전)에서는 `/staff`가 정적 프리렌더돼 이 흐름이 깨지는 결함이 있었다(리뷰에서 발견, `app/(auth)/staff/page.tsx`에 `export const dynamic = "force-dynamic"` 추가로 수정)
- [x] 세션에 역할이 staff로 기록된다 — `encodeSession({role:'staff', staffId})`
- [x] 사용 중지된 계정은 목록에 뜨지 않는다 — 실제 DB에 활성 1개·중지 1개 계정을 만들어 `is_active=true` 필터 쿼리로 활성 계정만 나오는 것 확인(테스트 데이터는 삭제함)

## 주의사항

- 이 사이트는 공장 내부용이라는 전제다. 외부 노출 시 최소한의 접근 제한(배포 단계 T-094)을 함께 검토한다.
- `SESSION_SECRET`이 빈 문자열이면 HMAC 서명이 위조 가능해진다(undefined는 에러로 막히지만 빈 문자열은 조용히 통과한다). `lib/auth/session.ts`가 32자 미만이면 에러를 던지도록 막아뒀다 — 배포 환경변수에 반드시 충분히 긴 무작위 값을 넣는다(`.env.example` 참고).
- 세션은 발급 시점에만 `is_active`를 확인한다. 사장님이 근무 중인 직원을 사용 중지시켜도 그 직원의 기존 세션은 최대 12시간(TTL) 동안 유효하다. 즉시 차단이 필요해지면 T-016에서 매 요청마다 재검증하는 방식을 검토한다.
