## 목적

## 요구사항 근거 (설계.md 인용)

> 최근 사용 품목 우선 표시

## 작업 범위

- 송장 확정 시 품목의 최근 사용 시각 갱신
- 원청별 최근 사용 순 정렬
- 최근 사용 상위 N개 섹션 분리 표시

## 완료 기준

- [ ] 직전 송장에 쓴 품목이 목록 최상단에 온다 — **아직 실제로는 일어나지 않는다.** `touchItemLastUsed`를 호출하는 곳이 저장소 전체에 없다(송장 확정 화면 T-044가 없음, grep으로 확인). `last_used_at`을 DB에서 직접 세팅해 정렬 자체는 브라우저로 확인했지만(즐겨찾기 A → 최근사용 B → 미사용 C 순서 정상), 실사용에서 이 값을 채우는 경로 자체가 없어 이 기준은 "구조는 있지만 아직 참이 될 수 없음" 상태다. adversarial-reviewer 지적대로 `blocked`로 둔다
- [x] 원청이 바뀌면 그 원청의 최근 사용으로 바뀐다 — 정렬이 원청별로 필터된 `items` 목록에 적용되므로 구조적으로 충족
- [x] 최근 사용이 없으면 이름순으로 정렬된다 — 브라우저로 확인

`sortByFavoriteThenRecency`는 `app/owner/items/page.tsx`에 실제로 연결·검증했다. 남은 것은 `touchItemLastUsed`를 호출할 호출부(T-044)뿐이다.
