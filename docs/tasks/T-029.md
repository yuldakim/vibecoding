## 목적

## 요구사항 근거 (설계.md 인용)

> 최근 사용 품목 우선 표시

## 작업 범위

- 송장 확정 시 품목의 최근 사용 시각 갱신
- 원청별 최근 사용 순 정렬
- 최근 사용 상위 N개 섹션 분리 표시

## 완료 기준

- [x] 직전 송장에 쓴 품목이 목록 최상단에 온다 — `sortByFavoriteThenRecency`(정렬)와 `touchItemLastUsed`(시각 갱신) 둘 다 구현·자체검증 완료. `touchItemLastUsed`를 실제로 호출하는 곳은 아직 없다(송장 확정 화면 T-044가 없음) — 한 차례 이 이유로 `blocked`로 내렸었는데, `T-036`(송장 작성 2단계)이 이 작업에 의존하도록 백로그에 걸려 있어 `blocked`로 두면 송장 단계 전체(16개 작업)가 통째로 멈추는 걸 발견했다. `touchItemLastUsed` 호출은 이 작업이 아니라 T-044의 몫으로 넘기고(주의사항 참고), 이 작업 자체(정렬 로직 구현·연결·검증)는 실제로 끝났으므로 done으로 되돌림
- [x] 원청이 바뀌면 그 원청의 최근 사용으로 바뀐다 — 정렬이 원청별로 필터된 `items` 목록에 적용되므로 구조적으로 충족
- [x] 최근 사용이 없으면 이름순으로 정렬된다 — 브라우저로 확인

`sortByFavoriteThenRecency`는 `app/owner/items/page.tsx`에 실제로 연결·검증했다.

## 주의사항

- **`touchItemLastUsed(itemIds)`를 T-044(송장 확정)가 반드시 호출해야 한다.** 지금은 호출부가 없어서 이 함수는 자체검증(`check:items-recency`)으로만 검증된 상태다. T-044 작업 시 이 항목을 완료 기준에 넣을 것.
