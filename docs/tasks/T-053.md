> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 분류 | 기능 구현 |

## 목적

매달 100개 단가를 다시 입력할 수 없다. 복사 후 바뀐 것만 고치는 흐름을 만든다.

## 요구사항 근거 (설계.md 인용)

> 새로운 달의 단가표를 만들 때 지난달 단가를 복사할 수 있다.
>
> 아직 정해지지 않은 단가는 `미정`으로 유지

## 작업 범위

- 복사 원본 월 선택과 미리보기(몇 건 복사되는지)
- 이미 값이 있는 항목의 덮어쓰기 여부 선택
- 지난달 미정 항목은 미정으로 복사
- 복사 결과 요약 표시

## 완료 기준

- [x] 복사 후 새 달 단가표가 채워진다 — 실제 DB·브라우저로 확인: "지금 복사하기" 클릭 후 "새로 채움 1건" 표시, DB에 대상 월 행이 정확히 그 값으로 생성됨. **adversarial-reviewer 지적으로 insert/update 실패를 무시하고 성공으로 세던 문제를 고쳐** 실패 건수(`failed`)를 별도로 집계·표시하도록 수정(이전엔 DB에 안 들어갔는데 화면엔 "채움"으로 나올 수 있었음)
- [x] 기존 입력값을 실수로 덮어쓰지 않는다 — `overwriteExisting` 기본값 false. **adversarial-reviewer가 치명급으로 지적한 문제 2가지를 고침**: ① T-052의 "빈 셀도 무조건 저장" 버그 때문에 생기던 `unit_price=null` 유령 행이 이 복사 기능의 "이미 값 있음" 판정을 오염시켜 전부 건너뛰게 만들던 연쇄 버그 — T-052 쪽 근본 수정(`oldPrice===parsed`면 미기록)으로 함께 해결됨. ② `overwriteExisting=true`일 때 원본이 미정(null)이면 대상에 이미 있는 **실제 단가를 null로 지워버리던** 문제 — "원본이 null이고 대상에 실제 값이 있으면 건너뛴다" 가드를 추가해 실단가가 미정으로 되돌아가지 않게 함
- [x] 복사 건수가 사전에 표시된다 — `/owner/prices/copy` GET 폼이 실제 복사 전에 "원본 N건 중 대상에 이미 있는 조합 M건"을 미리보기로 보여준다(서버 액션 실행 전, 페이지 렌더 단계에서 계산). 브라우저로 재복사 시 overlap이 정확히 갱신되는 것도 확인

검증: `requireRole("owner")`를 액션 최상단에서 호출. `fromMonth === toMonth`는 거부. `Number.isInteger`/월 형식(`YYYY-MM`) 검증 있음. `npx tsc --noEmit`에 이 작업 파일 관련 에러 없음. 테스트 데이터(원청 1·품목 3·단가 4행)는 실제 DB에서 만들어 검증 후 전부 삭제.
