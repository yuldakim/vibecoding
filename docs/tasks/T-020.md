## 목적

직원이 바뀌어도 사장님이 개발자 없이 계정을 관리하게 한다. 계정은 삭제하지 않고 사용 중지한다.

## 요구사항 근거 (설계.md 인용)

> 사장님이 직원용 계정을 여러 개 생성할 수 있다.
>
> 삭제 대신 `숨김`, `사용 중지`, `취소` 상태를 사용한다.

## 작업 범위

- 계정 목록(활성/중지 구분)
- 이름만으로 계정 추가
- 사용 중지·재사용 토글
- 중지된 계정이 로그인 화면에서 사라지는지 확인

## 완료 기준

- [x] 계정을 추가하면 로그인 화면에 바로 나타난다 — `addStaffAccount`가 `revalidatePath("/select")`·`revalidatePath("/staff")`를 호출. 목록 조회 자체도 `dynamic = "force-dynamic"`이라 캐시로 안 굳음
- [x] 중지해도 계정 행이 DB에 남는다 — `toggleStaffAccountActive`는 `update`만 쓴다(delete 없음). 실제 DB에 테스트 계정을 만들어 `is_active=false`로 바꾼 뒤 행이 그대로 남아있는 것을 확인(테스트 후 정리)
- [x] 삭제 버튼이 존재하지 않는다 — 화면·액션 어디에도 delete 호출이 없다(중지/재사용 토글 버튼만 있음)

## 주의사항

- **(리뷰에서 발견해 수정함)** `staff_accounts.name`에 유니크 제약이 없어 같은 이름으로 두 번 추가하면 `/select`에 구분 안 되는 버튼이 두 개 생기고, §24(삭제 금지)상 되돌릴 방법이 없었다. `addStaffAccount`가 같은 이름이 이미 있으면(중지된 계정 포함) 새로 insert하지 않고 그 행을 재사용(재활성화)하도록 고쳤다 — "재사용" 토글의 의도와도 맞는다.
