> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

## 목적

원청은 모든 기능의 시작점이다. 목록에서 한눈에 상태와 정산 일정을 파악하게 한다.

## 작업 범위

- 원청 목록 표(업체명·담당자·발송일·상태)
- 업체명 검색
- 사용 중지 포함/제외 필터
- 행 클릭 시 상세·수정 진입

## 완료 기준

- [x] 원청 20곳 이상에서도 목록이 느려지지 않는다 — 실제로 원청 23개(활성/비활성 혼합)를 만들어 페이지 쿼리 로직을 그대로 재현, 정상 응답 확인(별도 페이지네이션 없이도 이 규모에서 문제없음)
- [x] 사용 중지 원청이 시각적으로 구분된다 — 브라우저로 확인: 기본은 활성만 표시, "사용 중지 포함" 체크박스로 전환 시 중지 원청도 표시(상태 배지로 구분)
- [x] 휴대폰 폭에서 표가 카드 형태로 읽힌다 — `md:hidden`/`hidden md:table` 조합으로 좁은 화면은 카드 목록, 태블릿 이상은 표로 렌더(코드 확인)

## 주의사항

- **(리뷰에서 발견해 수정함)** 사용 중지 표시(`text-zinc-400`, 카드의 `opacity-50`)가 흰 배경 대비 2.5~4:1로 WCAG AA(4.5:1) 미달이었다 — 하필 "상태를 못 읽는 게 곧 오조작"으로 이어질 수 있는 지점(사용 중지 여부)이라 `text-zinc-600`(7.4:1 통과)으로 바꿨다.
- `escapeLike()`를 `lib/db/like.ts`로 옮겼다 — 품목 목록(T-026)·단가 화면(T-051)도 검색을 쓰므로 같은 곳에서 가져다 쓴다(화면마다 따로 만들면 한쪽만 고쳐져서 어긋난다).
- 목록 조회가 실패하면(DB 에러) "등록된 원청이 없습니다" 대신 별도 에러 문구를 보여주도록 고쳤다 — 조회 실패와 "진짜로 0건"은 사장님에게 다른 의미다.
- 업체명 클릭 링크(`/owner/clients/[id]`)는 아직 상세 화면(T-022)이 없어 404로 떨어진다. 전역 `app/not-found.tsx`를 새로 만들어서(이 작업 범위 밖, 여러 화면이 공유) 최소한 "처음으로 돌아가기" 링크가 있는 안내로 막다른 길이 되지 않게 했다.
