# T-033 · 여러 품목 합치기

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 1. 마스터 데이터 |
| 분류 | 기능 구현 |
| 우선순위 | P1 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-032](T-032.md) 품목명 변경(이력 보존) |
| 요구사항 근거 | §4 품목 관리, §4 품목명 변경 규칙 |
| 주요 위치 | `app/owner/items/merge/` |

## 목적

같은 제품이 조금씩 다른 이름으로 여러 개 등록된 상황을 정리한다. 합친 뒤에는 정산서에 최종 이름 하나만 나와야 한다.

## 요구사항 근거 (설계.md 인용)

> 여러 품목을 하나의 최종 품목으로 합치기
>
> 이전 이름은 원청에 보내는 엑셀에 표시하지 않는다.

## 작업 범위

- 합칠 품목 다중 선택과 최종 품목 지정
- merged_into 설정과 합치기 체인 해석
- 합치기 전 영향 미리보기(송장 수·정산 영향)
- 되돌리기 불가 경고와 확인 절차

## 완료 기준

- [ ] 합친 후 정산서에 최종 품목명 하나로 표시된다
- [ ] 과거 송장에는 각자의 당시 이름이 남는다
- [ ] 합치기 체인이 2단이어도 최종 품목이 정확히 해석된다

## 주의사항

- 단가는 품목별로 따로 있으므로 합친 뒤 단가 충돌 처리 규칙을 T-056에서 함께 확인한다.
