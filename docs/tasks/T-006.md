# T-006 · 마이그레이션: 원청

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 데이터 모델 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-004](T-004.md) 전체 DB 스키마 설계 확정 |
| 요구사항 근거 | §3 원청 관리 |
| 주요 위치 | `supabase/migrations/` |

## 목적

원청은 품목·송장·단가·정산·이메일 모두의 기준점이다. 정산 자동 발송일과 이메일 문구까지 원청별로 다르므로 한 테이블에 모은다.

## 요구사항 근거 (설계.md 인용)

> 원청 한 곳당 담당자는 한 명이고 납품 장소도 한 곳이다.
>
> 원청은 완전히 삭제하지 않고 `사용 중지` 처리한다.

## 작업 범위

- clients 테이블(업체명·담당자명·이메일·전화번호·주소)
- 정산 컬럼(자동 발송일, 사장님 확인 요청 기준일)
- 이메일 기본 문구 컬럼(제목·본문 템플릿)
- is_active(사용 중지) 컬럼과 기본값

## 완료 기준

- [x] 마이그레이션이 적용된다
- [x] 사용 중지된 원청도 과거 송장에서 조인 가능하다(삭제 아님 — `is_active`만 바뀌는 컬럼이고 물리 삭제 경로가 없음)
- [x] 자동 발송일이 1~31 범위로 제약된다(32 insert 시도 → check violation 확인)

## 주의사항

- 발송일이 31일인데 2월인 경우의 처리 규칙을 T-075에서 정한다. 여기서는 값만 저장한다.
