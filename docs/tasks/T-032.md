# T-032 · 품목명 변경(이력 보존)

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 1. 마스터 데이터 |
| 분류 | 기능 구현 |
| 우선순위 | P1 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-007](T-007.md) 마이그레이션: 품목·품목 이력, [T-027](T-027.md) 품목 추가·수정 |
| 요구사항 근거 | §4 품목명 변경 규칙, §25 품목명 변경·합치기 |
| 주요 위치 | `app/owner/items/rename/` |

## 목적

원청이 품목명을 바꿔도 이미 출력된 종이 송장과 사이트 기록이 어긋나면 안 된다. 이름 변경은 과거를 건드리지 않는 연산이어야 한다.

## 요구사항 근거 (설계.md 인용)

> 품목 이름을 변경하거나 합쳐도 기존 송장에는 당시 사용한 이름을 그대로 보존한다.
>
> 월말 정산서에는 연결된 이전 품목들을 합쳐서 최종 품목명만 표시한다.

## 작업 범위

- 이름 변경 화면과 변경 전후 미리보기
- item_aliases에 이전 이름 기록
- 기존 송장 줄의 품목명 스냅샷은 변경하지 않음 확인
- 변경 영향 안내('과거 송장 표시는 그대로, 정산서는 새 이름')

## 완료 기준

- [ ] 변경 후에도 과거 송장 상세에 옛 이름이 보인다
- [ ] 정산서에는 새 이름만 보인다
- [ ] 이전 이름이 검색에 걸린다

## 주의사항

- 이 기능은 되돌리기 어렵다. 실행 전 영향 범위(해당 품목이 쓰인 송장 수)를 먼저 보여준다.
