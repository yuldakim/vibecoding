## 목적

태블릿에서 쓰다 사무실 PC에서 마무리하는 사용 방식을 지원한다. 임시 송장은 번호가 없고 누구나 고칠 수 있다.

## 요구사항 근거 (설계.md 인용)

> 임시 송장: 송장번호가 없음, 어느 기기에서든 이어서 작성 가능, 모든 직원이 수정 가능, 자유롭게 삭제 가능

## 작업 범위

- 임시 저장 버튼과 자동 저장(입력 중 주기 저장)
- 번호 없이 draft 상태로 저장
- 다른 기기에서 열어 이어쓰기
- 동시 편집 시 마지막 저장 우선 규칙과 안내

## 완료 기준

- [ ] A 기기에서 저장한 임시 송장이 B 기기에서 열린다
- [ ] 임시 송장에 송장번호가 없다
- [ ] 저장 실패 시 사용자에게 분명히 알린다

## 주의사항

- 자동 저장 주기가 너무 짧으면 서버 부담이 커진다. 변경 후 3~5초 디바운스로 둔다.
- 임시 송장 삭제("자유롭게 삭제 가능")는 `invoice_lines`에 `on delete cascade`가 없다(확정 송장을 실수로 캐스케이드 삭제하는 걸 막으려는 의도적 설계, `docs/db-schema.md` 참고). 그래서 삭제할 때 `invoice_lines`를 먼저 지우고 `invoices`를 지워야 하며, 이 둘은 하나의 트랜잭션으로 묶는다 — 순서를 바꾸면 FK 위반으로 실패하고(안전하게 실패), 트랜잭션 없이 나눠서 하면 중간에 실패 시 줄만 사라진 빈 임시 송장이 남을 수 있다.
