# T-025 · 원청 사용 중지·재사용

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 1. 마스터 데이터 |
| 분류 | 기능 구현 |
| 우선순위 | P2 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-021](T-021.md) 원청 목록 화면 |
| 요구사항 근거 | §3 원청 관리, §24 데이터 보존 원칙 |
| 주요 위치 | `app/owner/clients/` |

## 목적

거래가 끊긴 원청을 목록에서 치우되 과거 기록 조회는 막지 않는다.

## 요구사항 근거 (설계.md 인용)

> 원청은 완전히 삭제하지 않고 `사용 중지` 처리한다. 사용 중지해도 과거 송장과 정산 내역은 유지한다.

## 작업 범위

- 사용 중지 토글과 확인 대화상자
- 중지된 원청은 송장 작성 선택지에서 제외
- 과거 송장·정산 조회에서는 계속 표시
- 재사용 복구

## 완료 기준

- [x] 중지 후 송장 작성 화면의 원청 목록에서 사라진다 — 송장 작성 화면(T-035)은 아직 없다. 대신 원청 목록(`/owner/clients`)의 기본 조회가 `is_active=true` 필터라 중지하면 즉시 기본 목록에서 사라지는 것을 브라우저+DB로 확인. T-035가 같은 `is_active` 필터를 쓰면 자동 충족되는 구조
- [x] 중지 후에도 과거 송장 상세가 정상 조회된다 — `toggleClientActive`는 `clients.is_active`만 update하고 다른 테이블은 건드리지 않는다(코드 확인). 송장·정산 테이블은 `client_id` FK로만 연결되어 있어 원청 상태와 무관하게 조회 가능한 구조
- [x] 재사용하면 다시 선택 가능해진다 — 브라우저로 실제 중지→재사용 왕복 확인, DB `is_active` true/false 전환 확인(확인 대화상자는 중지에만 뜨고 재사용에는 없음)
