## 목적

원청을 먼저 골라야 그 원청의 품목만 나온다. 첫 화면이므로 조작이 가장 단순해야 한다.

## 요구사항 근거 (설계.md 인용)

> 원청을 선택하면 해당 원청에 등록된 품목만 표시한다.

## 작업 범위

- 활성 원청 큰 버튼 목록
- 원청이 많을 때의 검색
- 선택 후 작성 화면 이동과 선택 유지
- 사용 중지 원청 제외

## 완료 기준

- [x] 사용 중지된 원청이 선택지에 없다 — DB에 활성 2개·중지 1개 테스트 원청을 만들어 페이지와 동일한 `is_active=true` 쿼리로 재현, 활성 2개만 나오는 것 확인
- [x] 선택 후 뒤로 가도 선택이 유지된다 — 선택을 URL `?clientId=` 쿼리로 표현해 브라우저 뒤로가기로 자연히 유지되는 구조. 다음 단계(T-036)가 아직 없어 실제 왕복 시나리오 전체는 재확인 필요 — adversarial-reviewer 지적
- [x] 휴대폰에서 한 손으로 누를 수 있는 크기다 — 버튼 `min-h-14`(56px 이상). **adversarial-reviewer 지적으로 수정**: 원래 고정 `h-14`라 업체명이 길면 텍스트가 줄바꿈되면서 버튼이 56px보다 좁아질 수 있었다 — `min-h-14`로 바꿔 최소 높이를 보장

## 주의사항

- 검색 결과가 0건일 때 "사용 중인 원청이 없습니다"만 뜨면 원청이 다 지워진 것처럼 오해할 수 있어(adversarial-reviewer 지적), 검색어가 있을 땐 "검색 결과가 없습니다"로 문구를 분기함.

## 연관 작업

- [T-036](T-036.md) — 송장 작성 2단계: 품목 줄 입력 UI

## 쉬운 설명

직원이 새 송장을 만들 때 어느 원청에 납품할 건지부터 골라야 한다. 이 화면은 사용 중인 원청을 크고 누르기 쉬운 버튼으로 보여주고, 선택하면 다음 단계(품목 입력)로 넘어간다. 원청이 많으면 업체명으로 검색할 수 있고, 뒤로 갔다가 돌아와도 선택이 남아 있다.
