# T-068 · 승인 후 수정 시 승인 자동 취소

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 4. 월말 정산 |
| 분류 | 기능 구현 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-067](T-067.md) 정산 최종 승인, [T-063](T-063.md) 정산 화면 단가 수정과 실시간 재계산 |
| 요구사항 근거 | §16 정산 승인과 자동 발송 |
| 주요 위치 | `lib/settlements/approval.ts` |

## 목적

사장님이 확인한 내용과 실제 발송본이 달라지는 사고를 원천 차단한다.

## 요구사항 근거 (설계.md 인용)

> 승인 후 발송 전에 정산 내용을 수정하면: 기존 승인 자동 취소, 상태를 `다시 확인 필요`로 변경, 사장님이 다시 최종 승인해야 함

## 작업 범위

- 정산 내역·단가 변경 감지
- **품목 합치기(T-033)·품목명 변경(T-032)도 감지 대상에 포함** — 합치기는
  `monthly_prices`를 직접 건드리지 않지만, T-056이 합쳐진 품목의 줄을
  최종 품목 단가로 재해석하게 되면 이미 승인된 정산의 금액이 뒤에서
  바뀔 수 있다(adversarial-reviewer가 T-033 리뷰에서 지적). 이 작업이
  단가·정산 내역 변경만 감지하면 이 경로를 놓친다.
- 승인 해제와 '다시 확인 필요' 상태 전이
- 자동 발송 대상에서 제외
- 사장님 알림 생성
- 변경 사유 기록

## 완료 기준

- [ ] 승인된 정산의 단가를 고치면 즉시 승인이 풀린다
- [ ] 다시 확인 필요 상태에서는 자동 발송되지 않는다
- [ ] 사장님 화면에 알림이 뜬다

## 주의사항

- 이미 발송된 정산서는 이 경로가 아니라 수정 정산서(T-080)로 간다.
