## 목적

사이트의 핵심 데이터다. 임시 송장(번호 없음)과 확정 송장(번호 있음)을 한 테이블에서 상태로 구분하고, 취소된 번호는 재사용하지 않는 일련번호 체계를 만든다.

## 요구사항 근거 (설계.md 인용)

> 송장번호는 원청이나 연도와 관계없이 계속 이어지는 일련번호를 사용한다.
>
> 취소된 번호는 다시 사용하지 않는다.
>
> 같은 품목과 같은 사이즈라도 비고가 다르면 별도 줄로 유지한다.

## 작업 범위

- invoices 테이블(원청 FK, 납품 날짜, 송장번호 nullable, 상태, 작성/출력/재출력/취소 시각)
- invoice_lines 테이블(품목 FK, 당시 품목명 스냅샷, 사이즈, 수량, 비고, 줄 순서)
- 송장번호용 Postgres 시퀀스와 6자리 0패딩 규칙
- 상태 enum(draft·confirmed·cancelled)과 확정 시 번호 필수 제약

## 완료 기준

- [x] 임시 송장은 번호 없이 저장되고 확정 송장은 번호가 반드시 있다 — `check` 2개로 draft/confirmed 양방향 강제. draft에 번호 채워 insert 시도·confirmed에 번호 없이 insert 시도 둘 다 실제 check violation으로 차단 확인
- [x] 시퀀스가 취소 후에도 되돌아가지 않는다 — `invoice_no_seq`는 `nextval`만 쓰고 `setval` 되돌리는 코드가 없음(코드 부재로 보장). draft→confirmed 전환 시 `nextval`로 정상 채번, 같은 번호 재사용 시도는 unique violation 확인
- [x] 같은 품목·사이즈·다른 비고가 별도 행으로 저장된다 — 실제 insert로 두 행 모두 보존 확인(병합 안 됨)

검증은 전부 실제 원격 DB(mbszzaxgkmrsgjoaedbo)에 임시 원청/품목/송장을 만들어 쿼리로 확인했고, 테스트 데이터는 모두 삭제해 정리했다. RLS도 두 테이블 모두 켜짐(`pg_class.relrowsecurity=true`) 확인.

## 주의사항

- 송장번호 표시 형식(000001)은 저장이 아니라 표시 시점에 패딩한다.
