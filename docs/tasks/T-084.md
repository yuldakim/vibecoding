## 목적

알림에서 바로 할 일로 이동해야 쓸모가 있다. 알림마다 다음 행동 버튼을 붙인다.

## 요구사항 근거 (설계.md 인용)

> 단가 미정 품목 존재, 단가 확인 요청서 발송 필요, 정산서 최종 확인 필요, 승인 후 발송 대기, 발송 예정일 경과, 이메일 발송 실패, 수정 정산서 확인 필요

## 작업 범위

- 알림 7종 표시와 우선순위 정렬
- 알림별 바로가기 버튼
- 읽음·해제 처리
- 알림 개수 배지

## 완료 기준

- [x] 7종이 모두 표시된다 — `notifications`에 7종 각각 1개씩 실제 insert 후 `getNotificationsForRole("owner")`와 동일한 쿼리로 조회, 7개 전부 조회되고 `OWNER_KIND_INFO`가 7종 전부에 라벨·href·priority를 매핑하는 것 확인(폴백 없음)
- [x] 알림에서 한 번에 해당 화면으로 간다 — 각 알림 제목이 `Link`로 해당 화면(`/owner/settlements` 또는 `/owner/prices`)에 연결됨. 두 화면 다 아직 없어 실제 이동은 못 봤지만 라우트는 백로그가 정한 위치와 일치
- [x] 처리하면 알림이 사라진다 — "확인" 버튼(서버 액션 `resolveNotification`)이 `is_resolved=true, resolved_at`을 설정하는 것을 동일 로직으로 실제 DB에 재현해 확인. `getNotificationsForRole`이 `is_resolved=false`만 조회하므로 처리 즉시 목록에서 빠짐. 테스트 데이터는 전부 정리함

## 주의사항

- 우선순위 순서(발송 예정일 경과 > 이메일 발송 실패 > 수정 정산서 확인 필요 > 정산서 최종 확인 필요 > 승인 후 발송 대기 > 단가 확인 요청서 발송 필요 > 단가 미정)는 설계 문서가 못박지 않아 내가 임의로 정한 것이다(`app/owner/notifications/kind-info.ts` 주석 참고) — 실제 사용해보고 사장님 피드백에 따라 바뀔 수 있다.
- 바로가기 링크는 전부 `/owner/settlements` 또는 `/owner/prices`(목록 화면)로 뭉뚱그려져 있다. 두 화면(T-061, T-051) 상세 진입점이 생기면 `ref_type`/`ref_id`를 이용해 특정 원청·정산서로 바로 가는 링크로 정교화할 수 있다.
- 알림 개수 배지는 이 화면 안에서만 보여준다(제목의 "(N)"). 네비게이션 바 배지는 범위 밖 — `components/nav/nav.tsx`는 건드리지 않았다.

## 주의사항

- **(리뷰에서 발견해 수정함)** `resolveNotification`이 `id`만으로 update해서, 사장님 화면에서 임의 id를 보내면 직원 전용 알림까지 해제될 수 있었다. `target_role in ('owner','both')`를 추가해 이 화면이 다룰 수 있는 알림만 해제하게 했다.
- 알림 바로가기 중 `/owner/settlements`(정산서 관련 5종)는 아직 화면이 없어 404로 떨어진다. 전역 `app/not-found.tsx`(다른 화면들과 공유)가 "처음으로 돌아가기" 안내를 보여주므로 막다른 길은 아니다 — T-061(월별 정산 목록 화면)이 만들어지면 이 링크들이 정상 동작한다.
- 우선순위 정렬 기준(발송 예정일 경과 > 이메일 실패 > … )은 설계 문서가 순서를 안 정해서 임의로 정한 것이다(`kind-info.ts` 주석 참고). 사장님이 실제로 써보고 순서가 안 맞으면 그때 조정한다.
