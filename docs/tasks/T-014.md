# T-014 · 사장님 모드 비밀번호 인증

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 인증·권한 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-005](T-005.md) 마이그레이션: 공장 정보·직원 계정, [T-013](T-013.md) 직원 로그인(계정 선택 방식) |
| 요구사항 근거 | §2 사장님, §25 사장님 비밀번호 입력 화면 |
| 주요 위치 | `app/(auth)/owner/` |

## 목적

사장님만 볼 수 있는 단가·금액·정산 정보를 가리는 경계를 만든다. 비밀번호는 해시 비교하고 무차별 입력을 막는다.

## 요구사항 근거 (설계.md 인용)

> 사장님은 별도의 아이디 없이 `사장님 모드`에서 전용 비밀번호를 입력한다.

## 작업 범위

- 사장님 모드 진입 화면(큰 숫자/문자 입력)
- 비밀번호 해시 검증 서버 액션
- 역할 'owner' 세션 발급과 자동 만료
- 연속 실패 시 지연·잠금 처리

## 완료 기준

- [ ] 올바른 비밀번호로 사장님 화면에 들어간다
- [ ] 틀린 비밀번호는 실패 횟수가 누적되고 지연된다
- [ ] 비밀번호가 평문으로 로그나 네트워크에 남지 않는다

## 주의사항

- 세션 만료 시간을 너무 짧게 잡으면 사장님이 정산 중에 튕긴다. 작업 중 갱신되도록 한다.
- T-005 시드가 `factory_settings.owner_password_hash`에 `'unset'`이라는 임시 문자열을 넣어뒀다(진짜 비밀번호가 아직 없어서). bcrypt/argon2 같은 해시 비교 함수를 쓰면 `'unset'`은 유효한 해시 형식이 아니라서 항상 불일치로 처리되지만, 혹시라도 단순 문자열 동등 비교로 구현하면 비밀번호란에 `unset`을 치면 사장님으로 로그인된다. 해시 검증 전에 `owner_password_hash === 'unset'`이면 무조건 거부하는 분기를 넣는다.
