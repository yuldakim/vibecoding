# T-014 · 사장님 모드 비밀번호 인증

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 인증·권한 |
| 우선순위 | P0 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-005](T-005.md) 마이그레이션: 공장 정보·직원 계정, [T-013](T-013.md) 직원 로그인(계정 선택 방식) |
| 요구사항 근거 | §2 사장님, §25 사장님 비밀번호 입력 화면 |
| 주요 위치 | `app/(auth)/owner/` |

## 목적

사장님만 볼 수 있는 단가·금액·정산 정보를 가리는 경계를 만든다. 비밀번호는 해시 비교하고 무차별 입력을 막는다.

## 요구사항 근거 (설계.md 인용)

> 사장님은 별도의 아이디 없이 `사장님 모드`에서 전용 비밀번호를 입력한다.

## 작업 범위

- 사장님 모드 진입 화면(큰 숫자/문자 입력)
- 비밀번호 해시 검증 서버 액션
- 역할 'owner' 세션 발급과 자동 만료
- 연속 실패 시 지연·잠금 처리

## 완료 기준

- [x] 올바른 비밀번호로 사장님 화면에 들어간다 — 실제 DB에 scrypt 해시를 넣고 서버 액션과 동일한 로직으로 검증: 정답 시 `owner_login_fail_count=0`·`owner_locked_until=null`로 리셋되고 세션 발급 경로로 진입함을 확인(테스트 후 시드값 `'unset'`으로 원복)
- [x] 틀린 비밀번호는 실패 횟수가 누적되고 지연된다 — 5회 연속 오답 시나리오를 실제 DB에 재현: 1~4회는 `fails`만 증가, 5회째 `owner_locked_until`이 5분 뒤로 설정됨. 잠금 중에는 정답을 넣어도 비밀번호 비교 자체를 안 하고 즉시 거부(`LOCKED`) 확인. 실패마다 `min(fails*500, 4000)`ms 지연 추가. (리뷰에서 발견: 최초 구현은 앱에서 "읽고 +1 해서 쓰는" 방식이라 동시 요청이면 카운트가 안 쌓이는 문제가 있었다 — `record_owner_login_failure()` 단일 UPDATE RPC로 교체해 원자적으로 만들고, `select record_owner_login_failure(...)`를 5번 연달아 실행해 정확히 5회째 잠기는 것을 다시 확인함)
- [x] 비밀번호가 평문으로 로그나 네트워크에 남지 않는다 — `verifyPassword`는 scrypt 해시만 비교하고 원문을 저장·로그하지 않음. `factory_settings.owner_password_hash`에는 `salt:hex` 형식만 저장(시드값 `'unset'`은 형식이 안 맞아 항상 거부)

## 주의사항

- 세션 만료 시간을 너무 짧게 잡으면 사장님이 정산 중에 튕긴다. 작업 중 갱신되도록 한다.
- T-005 시드가 `factory_settings.owner_password_hash`에 `'unset'`이라는 임시 문자열을 넣어뒀다(진짜 비밀번호가 아직 없어서). bcrypt/argon2 같은 해시 비교 함수를 쓰면 `'unset'`은 유효한 해시 형식이 아니라서 항상 불일치로 처리되지만, 혹시라도 단순 문자열 동등 비교로 구현하면 비밀번호란에 `unset`을 치면 사장님으로 로그인된다. 해시 검증 전에 `owner_password_hash === 'unset'`이면 무조건 거부하는 분기를 넣는다.
- **(리뷰에서 발견한 치명 결함, 수정 완료)** `lib/auth/password.ts`의 최초 구현은 `derivedHex`가 잘못된 hex 문자열이면 `Buffer.from(잘못된hex,"hex")`가 에러 없이 빈 버퍼가 되고, `scryptSync(plain, salt, 0)`도 빈 버퍼가 되어 `timingSafeEqual(빈,빈)`이 `true`를 반환했다 — 저장된 해시가 `"aa:zz"`처럼 손상되면 **아무 비밀번호나 통과**했다. 지금은 `derivedHex`가 정확히 64바이트 hex(128자)인지 검증하고, scrypt 출력 길이를 저장값이 아니라 항상 고정된 `KEY_LEN`으로 계산하도록 고쳤다. `owner_password_hash`를 손으로 만지는 코드(T-015 비밀번호 초기화 등)는 반드시 `hashPassword()`가 만든 값만 저장해야 한다.
