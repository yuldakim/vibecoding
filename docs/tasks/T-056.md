> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 단계 | 3. 봉제 단가 |
| 분류 | 기능 구현 |
| 우선순위 | P0 |

| 선행 작업 | [T-010](T-010.md) 마이그레이션: 월별 봉제 단가, [T-033](T-033.md) 여러 품목 합치기, [T-052](T-052.md) 단가 입력·수정 |

| 주요 위치 | `lib/prices/resolve.ts` |

## 목적

정산 전체가 이 함수 하나에 달려 있다. 합쳐진 품목, 이월 송장, 예외 단가까지 우선순위를 명확히 정의한다.

## 요구사항 근거 (설계.md 인용)

> 단가를 한 번 입력하면 해당 월의 같은 품목·사이즈가 포함된 모든 송장 줄에 자동 적용한다.
>
> 단가는 실제 납품월인 7월 단가 적용

## 작업 범위

- 적용 우선순위 정의(줄 예외 단가 > 해당 월 기본 단가 > 미정)
- 합쳐진 품목은 최종 품목 단가로 해석
- 이월 송장은 실제 납품월 단가 적용
- 단가 없음(미정) 반환 규약

## 완료 기준

- [x] 예외 단가가 있는 줄은 기본 단가를 쓰지 않는다 — `resolveLinePrice`에 `lineExceptionPrice`가 있으면 `monthly_prices` 조회 자체를 안 하고 바로 반환. 실제 DB(월 기본단가 12000 있는 상태에서 예외단가 3500 넘김)로 3500이 나오는 것 확인
- [x] 합쳐진 품목이 최종 품목 단가로 계산된다 — `final_item_id()` RPC로 합치기 체인을 따라간 뒤 그 id로 단가를 조회. 실제 DB로 품목 B를 A로 합친 뒤 B의 id로 조회해도 A의 단가가 나오는 것 확인
- [x] 이월 송장이 원래 납품월 단가로 계산된다 — 함수가 정산월이 아니라 파라미터로 받은 `deliveryDate`의 달로만 조회하므로, 호출자가 실제 납품일을 그대로 넘기기만 하면 자동으로 맞는다(별도 "이월 여부" 분기가 필요 없는 구조). 8월에 확정된 7월 31일 납품 송장이 7월 단가로 계산되는 것을 실제 DB로 확인

검증: `npm run check:prices-resolve`로 8개 케이스(기본 단가/이월/행 없음 미정/**행은 있는데 값이 null인 미정**/예외 단가/**소수점 예외 단가 거부**/**합치기(소스 품목이 자기 단가를 갖고 있어도 안 쓰임)**/**날짜 형식 오류 거부**) 전부 실제 Supabase로 확인. `npx tsc --noEmit`·`npm run lint`·`npm run build` 통과.

**adversarial-reviewer가 치명으로 지적해 고친 것**: 최초 구현은 (1) `final_item_id` RPC나 `monthly_prices` 조회가 실패하면 에러를 삼키고 원래(합쳐지기 전) 품목의 단가나 무조건 "미정"으로 조용히 넘어갔다 — 정산 금액의 기반 함수가 실패를 삼키면 틀린 금액이 정상 결과와 구분 안 되게 나간다. 이제 두 조회 모두 에러가 있으면 예외를 던진다. (2) `deliveryDate` 형식을 검증 안 해서, 호출자가 실수로 UTC 타임스탬프를 넘기면(KST 자정 경계) 달이 하루 밀려 조용히 틀린 달 단가가 잡힐 수 있었다 — `YYYY-MM-DD` 형식 검증을 추가해 거부한다. (3) `monthly_prices` 행이 있는데 값이 null(지난달 복사·직접 비움으로 생기는 정상 상태)인 경우와 행 자체가 없는 경우를 `source` 필드로 다르게 반환해서, 호출자가 `source==="undefined"`만으로 §12 단가 미정 목록을 만들면 전자를 놓칠 위험이 있었다 — 둘 다 `source: "undefined"`로 합쳤다. (4) `lineExceptionPrice`에 정수 검증이 없어 "금액은 정수" 원칙이 이 경로로 깨질 수 있었다 — 정수가 아니면 예외를 던지도록 추가. `app/owner/items/merge/price-impact.ts`(T-033 합치기 미리보기)도 단가 조회를 직접 중복 구현하던 것을 `resolveLinePrice` 재사용으로 바꿔서, 정산이 실제로 쓰는 로직과 미리보기가 어긋나지 않게 함.

## 쉬운 설명

송장 한 줄(원청·품목·사이즈·납품일)이 주어졌을 때 "얼마짜리로 계산해야 하나"를 정하는 함수다. 줄에 예외 단가가 따로 있으면 그걸 쓰고, 없으면 그 달의 기본 단가표를 찾아 쓰고, 그것도 없으면 "미정"으로 둔다. 품목이 다른 품목으로 합쳐졌으면 합쳐진 최종 품목의 단가표를 본다. "그 달"은 정산서를 만드는 달이 아니라 실제 납품일의 달이라서, 늦게 확정된 송장(이월)도 저절로 맞는 달 단가를 찾는다.

예외 단가는 `invoice_lines`가 아니라 `settlement_lines.override_unit_price`(이미 스키마에 있음, T-057이 정산 화면에서 채우는 값)에 저장된다 — §11 원문도 "사장님은 **정산 화면**에서 해당 줄의 단가를 직접 수정할 수 있다"고 돼 있어 송장 작성 단계가 아니라 정산 단계의 값이다. 이 함수는 그 값을 호출자(T-060)가 파라미터로 그대로 넘겨주는 형태로 만들었다. (adversarial-reviewer 지적: 최초 초안 문서에 "컬럼이 아직 없다"고 잘못 적었던 것을 수정함 — T-057이 같은 값을 `invoice_lines`에 또 만들면 예외 단가가 두 곳에 존재하게 되므로 주의)
