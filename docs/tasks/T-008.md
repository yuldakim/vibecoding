# T-008 · 마이그레이션: 사이즈

> 작업 상태의 SSOT는 저장소 루트의 `backlog.json`이다. 이 문서는 무엇을 왜 어떻게 만드는지만 다룬다.

| 항목 | 값 |
| --- | --- |
| 단계 | 0. 기반 구축 |
| 분류 | 데이터 모델 |
| 우선순위 | P1 |
| 예상 시간 | 30분 |
| 선행 작업 | [T-004](T-004.md) 전체 DB 스키마 설계 확정 |
| 요구사항 근거 | §5 사이즈 관리 |
| 주요 위치 | `supabase/migrations/` |

## 목적

사이즈는 품목과 독립적으로 선택되며, 직접 입력한 값도 다음 송장부터 목록에 나타나야 한다.

## 요구사항 근거 (설계.md 인용)

> 기본 목록에 없는 사이즈는 직접 입력할 수 있다. 직접 입력한 사이즈는 다음 송장부터 다시 선택할 수 있다.
>
> 품목마다 사용 가능한 사이즈를 미리 제한하지 않는다.

## 작업 범위

- sizes 테이블(이름, 기본 제공 여부, 정렬 순서)
- 싱글·슈퍼싱글·퀸·킹 시드
- 이름 유니크 제약과 공백 정규화 규칙

## 완료 기준

- [ ] 기본 4종이 시드로 들어간다
- [ ] 같은 이름 사이즈가 중복 생성되지 않는다
- [ ] 품목-사이즈 제한 테이블이 존재하지 않는다(의도적으로 제한하지 않음)

## 주의사항

- 수량 단위는 '장' 고정이므로 단위 컬럼을 만들지 않는다.
