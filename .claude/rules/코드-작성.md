# 코드 작성 규칙

## 줄 수 한도

한도는 `.claude/code-limits.json`에 있다. 저장할 때마다 hook이 검사한다.

| 영역 | 한도 | 경고 |
| --- | --- | --- |
| `components/**`, `app/**/*.tsx` | 200 | 170 |
| `app/api/**`, `app/**/route.ts` | 150 | 128 |
| `lib/**`, `hooks/**` | 250 | 213 |
| `tools/**`, `scripts/**` | 700 | 595 |
| 테스트 | 400 | 340 |
| `supabase/migrations/**` | 제한 없음 | — |
| 그 외 | 250 | 213 |

- **경고가 오면 그때 나눈다.** 한도를 넘긴 뒤 한꺼번에 쪼개는 것보다 싸다.
- 초과하면 hook이 재작업을 요구한다. 한도가 정말 안 맞는 상황이면 임의로
  넘기지 말고 **사용자에게 한도 조정을 요청한다.**
- 줄이는 방법: 독립적인 관심사를 별도 파일로, 반복 블록을 함수·컴포넌트로,
  한 파일이 두 가지 일을 하면 둘로.

## 스택 관례

- Next.js App Router. 서버에서 할 수 있는 일은 서버 컴포넌트·서버 액션으로.
- Supabase 스키마 변경은 **마이그레이션 파일로만** 한다. 대시보드에서 직접
  고치면 다음 사람이 재현할 수 없다.
- 비밀값은 환경변수로만 참조한다. 코드·문서·로그·커밋에 넣지 않는다.
  `service_role` 키는 서버 코드에서만 쓴다 — 클라이언트 번들에 들어가면 안 된다.

## 돈과 권한

- 금액은 **정수(원)** 로 다룬다. 부동소수점을 쓰지 않는다.
- 부가세·단가·이월 계산은 `.claude/rules/도메인-불변식.md`를 그대로 따른다.
  단가 해석(`lib/prices/resolve.ts`)과 정산 계산(`lib/settlements/calc.ts`)은
  테스트 대상이다 (T-092).
- 직원에게 금액을 감출 때는 **화면에서 숨기지 말고 응답에서 뺀다.**
  네트워크 탭에 단가가 실려 오면 실패다.

## 화면

주 사용자가 50대 후반이라는 제약은 요구사항이다.

- 본문 글씨 최소 18px, 버튼 높이 최소 56px, 터치 영역 44px 이상.
- 색 대비 WCAG AA 이상.
- PC·태블릿·휴대폰 세 폭에서 가로 스크롤이 생기지 않아야 한다.
- 라벨은 일상어로. `송장 만들기`, `정산서 보내기`처럼 쓰고 전문 용어를 피한다.
- 공통 컴포넌트(T-017)를 조합해 만든다. 화면마다 스타일을 새로 정하지 않는다.

## 검증

- 파일을 저장하면 그 파일만 lint가 돈다. 실패하면 **다음 작업으로 넘어가기 전에**
  고친다.
- 턴이 끝날 때 코드 변경이 있었으면 build가 돈다. 실패하면 턴을 못 끝낸다.
- 검증 전에 커밋해서 작업 트리를 깨끗하게 만들어도 소용없다 — build hook은
  이 턴에 커밋된 변경까지 검사 대상에 넣는다.
- lint·build는 `package.json`이 생기는 T-002 이후부터 실제로 돈다.
- **lint와 build는 문법만 본다.** 부가세를 줄마다 계산했거나 직원 응답에
  단가가 섞여 나가는 것은 둘 다 통과한다. 그래서 `done` 직전에
  `adversarial-reviewer`를 부른다 → `.claude/rules/서브에이전트.md`

## 문서

- 코드가 바뀌어 `docs/tasks/<id>.md`나 `설계.md`와 어긋나면 **같은 커밋에서**
  문서도 고친다.
- 하나의 사실은 한 곳에만 둔다. `설계.md`에 있는 내용을 다른 문서에 복사하지
  않고 절 번호로 가리킨다.
