# 도메인 불변식

`설계.md`에서 뽑은 **깨지면 돈이 틀어지는 규칙**들이다. 절 번호는 원문 위치다.
"비슷하게" 구현하면 안 되는 것만 모았다 — 판단이 서지 않으면 원문을 읽는다.

---

## 송장번호 (§7)

- 원청·연도와 **무관한 하나의 일련번호**다. 원청별·연도별로 나누지 않는다.
- `확정하고 인쇄`를 누르는 **그 순간** 부여한다. 임시 송장에는 번호가 없다.
- **취소된 번호는 재사용하지 않는다.** 번호는 뒤로 가지 않는다.
- 동시 확정에도 중복되면 안 된다 → **DB 시퀀스를 쓴다.** 앱에서 `max+1`을
  계산하면 두 사람이 동시에 확정할 때 같은 번호가 나온다.
- 표시 형식 `000001`은 저장이 아니라 표시 시점의 0 패딩이다.

## 출력한 송장 (§8)

- **출력한 송장은 수정할 수 없다.** 정정하는 유일한 방법은
  `기존 송장 취소 → 새 송장 작성 → 새 번호 부여 → 새로 출력`이다.
- 취소된 송장은 **월말 정산에서 제외**한다.
- 재출력물은 최초 출력물과 **완전히 동일**해야 한다. `재출력` 문구를 찍지 않는다.
- 작성·출력·재출력·취소 시각과 변경 전후는 **내부에만** 기록한다.
- 송장 인쇄물에 **단가와 금액을 표시하지 않는다.**
- A4 한 장에 같은 내용을 **위아래 2부**로 배치하고 가운데 절취선을 넣는다.

## 품목명 변경·합치기 (§4)

세 곳에서 서로 다르게 보여야 한다. 하나로 통일하면 요구사항 위반이다.

| 어디 | 무엇을 보여주나 |
| --- | --- |
| 과거 송장 | **그 송장을 쓸 당시의 이름** (스냅샷, 절대 안 바뀜) |
| 사이트 검색 | 새 이름으로 찾아도 옛 이름 송장이 **함께** 나옴 |
| 정산서 엑셀 | **최종 품목명만**. 이전 이름은 원청에게 보내지 않음 |

→ 송장 줄은 품목 id와 **당시 품목명 문자열**을 둘 다 가진다.
→ 합치기 체인이 2단 이상일 수 있다. 최종 품목까지 끝까지 따라간다.

## 단가 (§10, §11, §12)

- 단가는 **원청 × 품목 × 사이즈 × 적용 연월** 단위다. 같은 조합의 같은 달에
  기본 단가는 **하나뿐**이다.
- 단가는 **부가세가 빠진 공급가액 기준**이다.
- 적용 우선순위: **줄 예외 단가 > 그 달 기본 단가 > 미정**
- 예외 단가는 **그 송장 줄에만** 적용한다. 월별 단가표를 바꾸지 않는다.
- 단가 확인 요청 메일은 **사장님이 버튼을 눌러야** 나간다. 자동 발송 금지.
- 회신 이메일을 자동 수집하거나 엑셀에서 단가를 자동 추출하지 않는다 (1차 제외).

## 정산 계산 (§13, §14)

```
줄 공급가액   = 수량 × 적용 단가
전체 공급가액 = 모든 줄의 합
부가세        = 전체 공급가액 × 10%   ← 전체를 합산한 뒤 한 번만, 원 단위 반올림
최종 합계     = 전체 공급가액 + 부가세
```

- **줄마다 부가세를 계산해 합치면 값이 달라진다.** 반드시 전체 합산 후 1회다.
- 금액은 정수(원)로 다룬다. 부동소수점 금지.
- 정산 기간은 매월 **1일~말일**.
- 정렬은 **납품일 빠른 순 → 같은 날은 송장번호 빠른 순**.
- 같은 날 같은 품목도 **송장별·줄별로 각각** 표시한다. 합치지 않는다.
- **품목별 중간 합계를 표시하지 않는다.** 맨 끝에 전체 합계만.

## 승인과 발송 (§16, §21)

- **승인된 정산서만** 발송일에 자동 발송된다. 승인 없으면 발송일이 지나도 안 나간다.
- 발송일이 **지난 뒤** 승인하면 자동 발송하지 않는다. `지금 발송` 버튼을 눌러야 한다.
- 승인 후 발송 전에 내용이 바뀌면 **승인이 자동 취소**되고 `다시 확인 필요`가 된다.
- **이미 발송한 정산서는 수정하거나 덮어쓰지 않는다.** 수정본을 새로 만든다.
  `A원청_2026년07월_정산서.xlsx` → `A원청_2026년07월_정산서_수정1.xlsx`
- 수정본도 사장님이 다시 승인해야 나간다.

## 이월 (§17)

특정 월의 정산서가 **승인된 뒤** 그 달 날짜로 새 송장이 확정되면:

- 기존 정산서를 **건드리지 않는다.**
- 그 송장은 **다음 달 정산서**로 넘긴다.
- **납품일은 실제 날짜 그대로**(7월 31일) 표시한다.
- 비고·구분에 **`전월 이월`** 을 표시한다.
- 단가는 **실제 납품월(7월) 단가**를 쓴다. 8월 단가가 아니다.
- 7월 단가가 없으면 단가 미정 목록에 들어간다.
- 판정 기준 시각은 **승인 시각**이다 (발송 시각이 아니다).

## 권한 (§2, §26)

사장님만 보는 것: **봉제 단가, 공급가액, 부가세, 정산 총금액, 정산서 상세**

- **화면에서 감추는 것으로는 부족하다.** 직원 세션의 API 응답에서 금액 필드를
  아예 빼고, DB 수준에서도 막는다. 네트워크 탭에 단가가 보이면 실패다.
- 직원은 비밀번호 없이 계정 선택만으로 로그인한다.
- 사장님은 아이디 없이 전용 비밀번호만 입력한다.
- **직원별 활동을 추적하지 않는다.** 기록에는 `직원`/`사장님`만 남긴다.
- 직원 알림은 3종뿐이고 금액이 들어가면 안 된다. 발송 예정일 **7일 전**부터 표시.
- `사장님께 전달했어요` 같은 확인 버튼은 만들지 않는다.

## 삭제 금지 (§24)

다음은 **절대 물리 삭제하지 않는다.** 상태로만 다룬다.

원청 · 품목 · 직원 계정 · 확정 송장 · 발송된 정산서 · 월별 단가

- 삭제해도 되는 것은 **임시 송장**뿐이다.
- 사용 중지·숨김·취소해도 **과거 기록은 항상 조회 가능**해야 한다.

## 기타 고정값

- 수량 단위는 항상 **`장`** 이다. 단위 컬럼을 만들지 않는다 (§5).
- 품목마다 쓸 수 있는 사이즈를 **제한하지 않는다** (§5).
- 같은 품목·같은 사이즈라도 **비고가 다르면 별도 줄**로 유지한다 (§6).
- 원청 한 곳당 담당자 1명, 납품 장소 1곳 (§3).

## 1차 범위에서 제외 (§26)

요청받지 않는 한 **만들지 않는다.** 설계에서 의도적으로 뺀 것들이다.

반품 기록 · 반품 확인서 출력 · 서명된 종이 송장 사진 저장 ·
원청 이메일 회신 자동 수집 · 이메일/엑셀에서 단가 자동 추출 ·
과거 데이터 이전 · 직원별 활동 추적 · 직원의 금액 열람 ·
정산서 PDF 발송 · 품목코드 관리

반품은 "제품을 다시 받아 고쳐 보내는 일"이라 정산 대상이 아니다. 수량이나
금액을 차감하지 않으므로 사이트에 기능을 두지 않는다 (§9).
